# Bookmark Sync · 书签同步

将浏览器书签保存到自己的 GitHub 或 Gitee 仓库，通过 JSON 快照在设备之间同步。发生冲突时，在独立合并页左右对照、勾选保留内容，不必手动编辑 JSON。

适用于 Microsoft Edge 和 Google Chrome。项目采用 Manifest V3 与原生 JavaScript 模块，无需构建即可加载。

> 本文对应当前源码。扩展声明版本为 `0.2.0`，源码中的新增功能不代表已经发布到扩展商店。

## 功能概览

| 功能 | 说明 |
| --- | --- |
| 仓库同步 | 分别配置 GitHub、Gitee，使用自己的仓库、分支和快照路径 |
| 手动推送 | 推送到默认平台，或全部已配置平台 |
| 手动拉取 | 从选定平台导入本地；检测到冲突时进入合并页 |
| 可视化合并 | 左侧本地、右侧云端，逐项勾选，下方实时预览 |
| 定时自动推送 | 最小间隔 15 分钟，只推送，不自动拉取 |
| 时光胶囊 | GitHub / Gitee 文件提交历史，每页 10 条，展示书签新增、删除与变更 |
| 离线备份 | 导出、导入书签 JSON 快照 |
| 配置迁移 | 导出、导入平台配置，导出默认包含 Token |
| 状态展示 | 本地与云端书签数量、最近同步信息及工具栏状态徽章 |

当前设置界面提供“仪表盘”“时光胶囊”“基本设置”。外观设置入口暂时隐藏，使用默认浅色主题，其他主题代码仍保留。

当前没有模拟推送、模拟拉取或模拟合并页面。真实冲突合并功能不受影响。

## 安装与更新

扩展清单声明最低 Chromium 版本为 `114`，建议使用较新的 Edge 或 Chrome。

1. 下载或克隆项目，保留完整目录结构。
2. Edge 打开 `edge://extensions`；Chrome 打开 `chrome://extensions`。
3. 开启开发者模式，选择“加载解压缩的扩展”或“加载已解压的扩展程序”。
4. 选择包含 `manifest.json` 的项目根目录。
5. 将扩展固定到工具栏，点击图标打开弹窗。

更新源码后，在扩展管理页点击“重新加载”，关闭旧的设置页、合并页后重新打开。加载项目不需要执行打包或依赖安装。

## 连接仓库

从弹窗右上角设置按钮进入“基本设置”，选择 GitHub 或 Gitee，填写对应参数。

| 参数 | 填写方式 |
| --- | --- |
| Token | 原始访问令牌，不加 `Bearer` 或 `token` 前缀 |
| 用户/组织 | 仓库 URL 中的所有者名称，不是显示昵称 |
| 仓库名 | 仓库名称，不填写完整 URL 或 `.git` 后缀 |
| 分支 | 仓库内已经存在的分支，例如 `main` 或 `master` |
| 文件路径 | 仓库内的具体文件路径，例如 `bookmarks/snapshot.json`，不能是目录 |

填写后点击“保存设置”，确认已保存，再点击“测试连接”。平台配置分别保存；基本设置不是所有输入都自动保存，离开前请检查保存状态。

### 权限要求

GitHub 仓库建议使用仅授权目标仓库的 Fine-grained Token。创建或编辑时选择目标仓库，**在权限区域点击 `Add permissions`，添加 `Contents` 并设置为 `Read and write`**。不要只选仓库而遗漏添加内容读写权限；同时确认令牌的仓库元数据读取权限。

Gitee 使用有目标仓库内容读写权限的私人令牌。无论哪种平台，令牌所属账号都必须有权访问目标仓库；令牌失效或授权不足时，需要在平台侧调整。

测试连接成功只表示对应连接检查通过，不保证后续所有文件读取、创建和写入操作都能成功。分支、路径、权限与远端文件格式仍需正确。

### 首次同步

1. 建议先从“备份与迁移”导出本地书签 JSON。
2. 确认仓库和目标分支存在。新建仓库时可用 README 初始化分支。
3. 在弹窗点击“推送到云端”。远端快照不存在时会自动创建，不需要手动建立空 JSON 文件。
4. 如果云端已有其他书签内容，按合并页提示逐项选择，不会强制覆盖。
5. 完成一次手动同步后，再按需开启自动推送。

只有 README 而没有快照文件是正常的首次推送场景。先执行拉取则会提示远端文件不存在。

## 日常同步

弹窗显示本地书签数量、已配置平台的云端数量和最近同步状态。未配置仓库时，“连接云端仓库”会打开基本设置。

| 操作 | 写入位置 | 注意事项 |
| --- | --- | --- |
| 推送到云端 | 当前平台或全部已配置平台 | 不修改本地书签 |
| 拉取到本地 | 浏览器本地标准书签目录 | 导入快照会替换相应目录内容，先检查来源并备份 |
| 推送冲突合并 | 当前发生冲突的平台 | 其他平台不会随合并提交一起更新 |
| 拉取冲突合并 | 浏览器本地书签 | 云端不会被改写 |

多平台配置时，可在弹窗“高级选项”选择默认平台和“推送到全部已配置平台”。自动推送沿用保存的推送目标，拉取始终只针对一个平台。

多平台推送不是原子操作：部分平台可能已经成功，另一些平台发生冲突或失败。请根据提示分别处理，不能把一次失败理解为所有平台都没有更新。

## 冲突合并

**强制推送与强制拉取已移除。** 手动同步发现冲突后会打开独立合并页。

1. 查看左右对齐的差异：左侧是本地，右侧是云端。
2. 勾选本地保留本地版本，勾选云端保留云端版本；两侧都勾选则两边都保留。
3. 如果整项都不要，明确点击“两边都不保留”。取消所有勾选只会恢复为待确认，不代表删除。
4. 下方实时显示合并后的书签树与数量。未确认项暂不计入预览。
5. 完成所有差异确认后，可下载合并草稿、校验结果，勾选确认再提交。

相同内容自动保留。单边存在的书签也需要确认，因为当前合并不是基于共同祖先的三方合并，不能可靠判断它是新增还是被另一侧删除。以整个文件夹呈现的差异项，其选择作用于整个文件夹。

JSON 仅在折叠区域内只读展示，无需编辑。书签使用带缺口图标，文件夹使用文件夹图标；这些图标不是复选框。

### 合并后写到哪里

- 从推送进入：点击“提交合并结果”，只更新当前云端，本地保持不变。如需同步到本地，请再拉取，有冲突时继续通过合并页确认。
- 从拉取进入：点击“应用到本地书签”，只更新本地，云端保持不变。如需让云端也保存该结果，请再推送并处理可能出现的冲突。

### 安全保护

- 提交前检查仓库配置、本地内容和远端版本；发生变化时拒绝旧结果，需要重新读取再选择。
- GitHub / Gitee 推送提交遇到版本冲突时，不会换用最新版本号重试覆盖。
- 应用前把两侧快照保存到扩展本地存储的 `lastMergeBackup`。这是最近一次备份，不是多版本备份列表，也没有独立的一键恢复入口。
- 拉取导入前再次检查本地版本，导入后校验；失败会尝试回滚，并报告回滚失败情况。
- 完全重复的目录会触发保护检查，不能通过强制模式绕过。

这些保护不能替代离线备份。关闭合并页不会自动保存未提交选择；重新读取会清除选择，请先按需下载已完成的结果。

## 时光胶囊

在设置页打开“时光胶囊”，选择 GitHub 或 Gitee。

- 按当前配置的仓库、分支和文件路径读取提交记录，每页 10 条，可上一页、下一页翻页。
- 选择一条提交，查看作者、时间、提交信息，以及该快照相对第一个父提交的书签新增、删除与变更。
- 历史快照读取失败或格式无效时，显示无法比较的原因，不把错误伪装成零变化。
- 大量差异会截断展示，并提示未展示的数量。

这是云端文件提交历史，不是每次点击同步的操作日志。内容相同的推送不会创建新提交；拉取和应用到本地也不会产生云端提交。刚推送完成可点击“刷新记录”，并检查平台、分支和路径是否一致。

当前没有从时光胶囊直接恢复某个历史版本的功能。

## 自动推送与功能边界

在基本设置中开启自动推送并保存，间隔最小 15 分钟。自动任务只执行推送，冲突时停止并提示，不会自动拉取或替用户选择合并结果。

底层还保留书签变更防抖推送、启动检查、通知、清空与恢复等能力，但当前基本设置没有展示这些配置或操作入口，不应按旧文档寻找对应按钮。

本项目只支持 GitHub 和 Gitee 仓库。旧版其他平台配置不再参与同步或配置导出；若旧配置的默认平台已不受支持，会回退到 GitHub 并关闭定时、变更触发及全平台自动推送选择。请重新确认仓库和推送目标，再按需启用自动推送。

## 备份、迁移与隐私

基本设置的“备份与迁移”提供两类文件：

| 文件 | 内容 | 用途 |
| --- | --- | --- |
| 书签 JSON | 书签快照，不包含平台 Token | 离线备份与恢复 |
| 配置 JSON | 平台连接参数、Token 与同步设置 | 换设备迁移配置 |

**配置导出默认包含 Token，没有“包含 Token”勾选项。** 不要提交到代码仓库、公开分享、贴到问题反馈或截图中。如果令牌已泄露，应在平台撤销并重新生成。

配置保存在浏览器的 `chrome.storage.local`，不是密码保险库。卸载扩展可能清除配置及扩展内备份，卸载前请导出需要保留的数据。

书签快照写入自己的仓库，建议使用私有仓库并授予最小必要权限。同步只处理标准书签根目录，不修改 Edge 工作区等非标准目录；这也意味着工作区数据不包含在同步范围内。

## 常见问题

| 问题 | 检查方向 |
| --- | --- |
| `401 / Bad credentials` | Token 是否有效、过期、复制完整；不要把示例占位符当令牌 |
| `403` 或无权读写 | 目标仓库授权、内容读写权限、账号权限及平台限制 |
| 测试连接成功，但推送失败 | 测试连接不是写入测试；继续检查分支、路径、写权限与远端数据 |
| 远端文件不是合法 JSON | 确认路径指向书签快照，而不是 README、空文件或其他内容；不要手工创建空 JSON |
| 远端路径指向目录 | 填写具体文件路径，例如 `bookmarks/snapshot.json` |
| 拉取时远端文件不存在 | 先推送创建快照，或检查平台、分支和路径 |
| 合并时提示数据已变化 | 先下载已完成的草稿，再重新读取两侧数据并选择 |
| 推送后时光胶囊没有新记录 | 是否内容相同、只应用到了本地，或查看了不同平台、分支与路径 |
| 看不到外观设置 | 当前主动隐藏，仅启用默认浅色主题 |
| 原来的模拟链接不能使用 | 模拟功能已移除，真实合并页由同步冲突触发 |

## 开发与验证

代码结构：

```text
src/
  background/     同步调度、冲突保护、消息路由、历史查询
  core/           配置、存储、书签导入导出、快照与差异计算
  providers/      GitHub、Gitee 仓库适配
  ui/
    popup/        工具栏弹窗
    options/      仪表盘、时光胶囊、基本设置
    merge/        真实冲突合并页
    shared/       界面共享逻辑
tests/            自动化测试
```

本地测试命令：

```sh
npm test
git diff --check
```

测试覆盖合并选择、方向隔离、过期版本拦截、导入校验与回滚、历史差异和分页等逻辑。自动化测试不能替代浏览器实测，也不代表已验证真实仓库网络请求。

发布包需要包含 `manifest.json`、`src`、`assets` 和 `_locales` 等运行资源。不要把临时预览目录、测试数据、个人配置或 Token 打进发布包。
