# Bookmark Sync（Chrome / Edge）

将浏览器书签同步到你自己的 GitHub 仓库、Gitee 仓库或 GitHub Gist。支持手动推送/拉取、书签变更自动推送（防抖）、定时推送兜底、冲突预览与强制同步、工具栏徽章与系统通知。

> 📖 第一次使用？[USAGE.md 详细使用文档](USAGE.md) 从零讲解每个平台要配置什么（GitHub / Gitee 令牌怎么建、权限怎么勾）、日常用法与故障排查。

## 项目说明

插件会把本地书签导出为快照 JSON，并读写到你选择的云端位置：

- **GitHub / Gitee 仓库模式**：写入仓库指定路径（默认 `bookmarks/snapshot.json`）
- **GitHub Gist 模式**：写入一个私有 Gist 中的指定文件（默认 `bookmarks.json`）

核心动作：

- `推送`：将本地书签写入云端
- `拉取`：将云端快照导入本地并覆盖
- `导出书签 JSON`：离线备份
- `导入书签 JSON`：离线恢复

代码为纯 ESM 模块化结构（`src/core` 共享逻辑、`src/providers` 云端平台、`src/background` 后台服务、`src/ui` 界面），无构建步骤，加载根目录即可运行。

## 功能总览

已支持：

- **三种云端后端**：GitHub 仓库 / Gitee 仓库 / GitHub Gist，可分别配置、并存使用
- 手动推送/拉取，推送可选“仅默认平台”或“同时推送到全部已配置平台”
- **书签变更自动推送**：增删改书签后按防抖窗口（默认 60 秒，可配 30–300 秒）自动推送
- 定时自动推送兜底（最小 15 分钟）
- **启动时检查云端更新**（可选）：仅提醒，绝不自动导入
- 冲突检测、差异预览、手动确认后强制同步
- **工具栏徽章**：待推送 / 成功 / 失败 / 冲突状态一目了然
- **系统通知**：自动推送失败默认提醒，成功与手动完成可选
- **清空本地书签**：带自动下载备份 + 本地双保险快照，可一键恢复
- 设置页“配置导出 / 导入”（含 Token 与自动同步参数）
- 弹窗显示本地及各已配置平台的云端书签数量
- “查看云端历史”链接：直达仓库提交历史 / Gist 修订历史
- 导入/导出仅处理浏览器标准书签根节点，不修改 Edge 的 `workspace folder`

边界说明（明确不做）：

- 自动同步只做“推送”，云端更新只提醒、**不会自动拉取覆盖本地**
- 拉取必须选择单个平台执行
- 冲突时自动任务会跳过，不会自动强制覆盖
- Gist 的写入接口无并发保护（详见 [GitHub Gist 配置流程](#github-gist-配置流程)）
- 不支持 WebDAV/S3、Firefox、全量多语言界面

## 安装插件

需要 Chrome / Edge 114 及以上版本。

### Chrome

1. 打开 `chrome://extensions`
2. 开启“开发者模式”
3. 点击“加载已解压的扩展程序”
4. 选择本项目根目录（含 `manifest.json`）

### Edge

1. 打开 `edge://extensions`
2. 开启“开发人员模式”
3. 点击“加载解压缩的扩展”
4. 选择本项目根目录（含 `manifest.json`）

发布打包注意：

- 商店上传包必须包含 `_locales` 目录（如 `_locales/zh_CN/messages.json`）
- 若 `manifest.json` 中存在 `default_locale` 但压缩包缺少 `_locales`，会触发包校验错误

## 配置说明（设置页）

点击弹窗右上角齿轮进入设置页。设置页负责连接参数与自动化开关，不执行推送/拉取动作。

### 平台连接

| 字段 | 适用平台 | 说明 |
|---|---|---|
| 同步提供方 | 全部 | 当前编辑哪一套平台配置（GitHub / Gitee / GitHub Gist） |
| Token | 全部 | 平台访问令牌（直接粘贴原始 Token，不要带 `Bearer` 前缀） |
| 用户/组织 | GitHub / Gitee | owner 名称 |
| 仓库名 | GitHub / Gitee | repo 名称 |
| 分支 | GitHub / Gitee | 目标分支，如 `main` / `master` |
| 文件路径 | GitHub / Gitee | 快照文件路径，默认 `bookmarks/snapshot.json` |
| Gist ID | Gist | 留空则首次推送自动创建私有 Gist 并回填 |
| 文件名 | Gist | Gist 内的快照文件名，默认 `bookmarks.json` |

各平台配置分别保存；填写后请先 `保存设置` 再 `测试连接`。

### 自动同步

- `定时自动推送`：开关 + 间隔分钟数（最小 15，低于自动校正）
- `书签变更后自动推送`：开关 + 防抖秒数（30–300，默认 60）。连续修改书签会合并为一次推送
- `启动时检查云端更新`：浏览器启动时比对云端版本，云端更新时通知提醒并点亮徽章，不会自动导入

### 通知

- `自动推送失败时通知`：默认开启
- `自动推送成功时通知`：默认关闭
- `手动操作完成时通知`：默认关闭

### 备份与迁移

- `导出 / 导入书签快照`：书签数据的离线备份与恢复
- `导出 / 导入平台配置`：迁移全部平台配置（含 Token）与自动同步设置。导出文件包含敏感令牌，请仅在可信环境保存

### 危险操作

- `清空本地书签`：详见 [清空本地书签](#清空本地书签)

## 弹窗同步说明

弹窗自上而下：

1. **状态条**：最近同步时间 + 同步状态圆点（与工具栏徽章一致）
2. **数量卡片**：本地书签数量 + 每个已配置平台的云端数量（未配置的平台不显示）
3. **推送 / 拉取**两颗主按钮：作用于“默认平台”（按钮下方小字标注当前目标）
4. **高级选项**（折叠区，仅配置一个平台时自动隐藏）：
   - 默认平台下拉：切换推送/拉取作用的平台
   - `推送到全部已配置平台`：勾选后推送会并行发往所有已配置平台（该选择会保存，并同样作用于自动推送）
   - `查看云端历史`：跳转当前平台的提交 / 修订历史页
5. **冲突预览与状态区**：检测到冲突时展示差异与确认操作

## 自动同步说明

三条自动化路径可并存：

| 路径 | 触发条件 | 行为 |
|---|---|---|
| 变更触发推送 | 书签增删改后，防抖窗口结束 | 推送到默认平台或全部已配置平台 |
| 定时推送 | 固定间隔（≥15 分钟） | 同上，作为兜底 |
| 启动检查 | 浏览器启动 | 仅比对云端版本并提醒，不做任何写入 |

规则：

- 自动任务仅执行“推送”；推送目标沿用弹窗中保存的设置
- 检测到冲突时自动推送会跳过并点亮橙色徽章（可开启通知），需要你手动处理
- 拉取导入书签期间不会误触发变更推送（内置回环抑制）

## 徽章与通知

工具栏图标上的徽章表示当前同步状态：

| 徽章 | 含义 | 清除时机 |
|---|---|---|
| `…`（灰） | 书签已变更，等待防抖推送 | 推送完成后 |
| `✓`（绿） | 自动推送成功 | 约 30 秒后自动清除 |
| `!`（橙） | 自动推送因冲突跳过 | 打开弹窗或手动同步成功后 |
| `!`（红） | 自动推送失败 | 打开弹窗或手动同步成功后 |

系统通知开关见设置页“通知”分组；“启动时检查云端更新”的提醒不受通知开关限制（该功能本身即为显式开关）。

## 首次同步建议

首次请先确定“以哪一边为准”：

- 以本地为准：执行 `推送`
- 以远端为准：执行 `拉取`

补充：

- 三种平台首次推送都会自动创建远端快照文件（Gist 模式还会自动创建 Gist 本身），无需手动预建
- 建议先完成一次手动推送建立基线，再开启自动推送

## 冲突处理

检测到冲突时会显示差异预览（本地/远端数量及样例）并弹出确认。

你可以：

1. 取消本次操作
2. 选择强制继续（覆盖另一侧）

建议先执行一次 JSON 导出备份，再做强制同步。自动推送遇到冲突只会跳过并提醒，永远不会自动强制覆盖。

## 清空本地书签

入口：设置页 `危险操作` 卡片。适合“想让本机完全以云端为准”前的清场操作。

安全流程：

1. 点击后插件先**自动下载一份书签备份 JSON**
2. 同时在扩展存储内保留一份清空前快照（双保险）
3. 确认框明确显示将删除的书签数量
4. 仅清空三个标准书签根（书签栏 / 其他书签 / 移动设备书签），不碰 Edge 工作区目录
5. 清空动作**不会触发变更自动推送**（不会把空书签树推上云端）

误操作时点击旁边的 `恢复最近清空的书签` 即可从内置快照还原；也可用下载的备份 JSON 手动导入恢复。

## GitHub 仓库配置流程

### 1. 创建仓库

1. 在 GitHub 新建仓库（建议 `Private`）
2. 记录 owner、repo、默认分支（通常 `main`）

### 2. 创建 Token

路径：
`Settings -> Developer settings -> Personal access tokens -> Fine-grained tokens`

关键权限：

1. `Resource owner` 选择当前仓库所属账号
2. `Repository access` 选 `Only select repositories`
3. 选择目标仓库
4. 在 `Repository permissions` 区域点击 `Add permissions`
5. 添加 `Metadata` 权限并设为 `Read-only`
6. 添加 `Contents` 权限并设为 `Read and write`
7. 生成后复制 Token（仅显示一次）

注意：

- 如果没有先点击 `Add permissions`，下面的权限项不会真正加入 Token
- 漏掉 `Metadata` 或 `Contents`，测试连接/读写文件时可能出现 `401` 或 `403`
- 在插件里请直接粘贴原始 Token，不要带 `Bearer` 或 `token` 前缀

### 3. 在设置页填写并测试

1. 打开扩展弹窗，点击右上角齿轮
2. 选择 `GitHub`
3. 填写 Token / owner / repo / branch / path
4. 点击 `保存设置`
5. 点击 `测试连接`

## Gitee 配置流程

1. 在 Gitee 新建仓库（建议私有）

## GitHub Gist 配置流程

Gist 模式配置最简单：只需一个 Token，连仓库都不用建。

### 1. 创建 Token（必须用 classic）

路径：
`Settings -> Developer settings -> Personal access tokens -> Tokens (classic) -> Generate new token (classic)`

1. 勾选 **`gist`** 这一项 scope 即可，其余都不需要
2. 生成后复制 Token

注意：**必须使用 classic 类型的 PAT**。Fine-grained Token 目前不支持 Gist API，用它会一直 `401/403`。

### 2. 在设置页填写并测试

1. 选择 `GitHub Gist`
2. 填写 Token；`Gist ID` 留空即可（首次推送会自动创建私有 Gist 并把 ID 回填到配置）；文件名默认 `bookmarks.json`
3. `保存设置` → `测试连接`
4. 执行一次 `推送`，完成初始化

### 使用须知

- 插件创建的是**私有 Gist**；若你手动指定了一个公开 Gist，测试连接会给出警告，建议改用私有
- 超过约 1MB 的快照会走 Gist 原始内容接口自动拉取完整数据，无需关心
- 边界：Gist 的写入接口没有并发写入保护（不同于仓库模式的原子校验）。推送前的冲突预检仍然生效，但两台设备在同一瞬间推送时，后写入者会覆盖先写入者。多设备高频写入场景建议使用 GitHub / Gitee 仓库模式

## 常见问题

| 现象 | 原因 | 处理方式 |
|---|---|---|
| 弹窗高级选项里看不到某平台 | 对应平台配置未填完整 | 先到设置页补齐必填项并保存 |
| 弹窗数量卡片没有某平台 | 未配置的平台不显示数量卡片 | 正常行为，配置后自动出现 |
| 改了书签但没自动推送 | 变更自动推送默认关闭，或防抖窗口未到 | 设置页开启“书签变更后自动推送”，等待防抖秒数（默认 60）；若徽章为橙色 `!` 说明因冲突跳过，需手动处理 |
| 收不到系统通知 | 通知开关未开，或系统禁止了浏览器通知 | 检查设置页“通知”分组与操作系统的浏览器通知权限 |
| 输入 11 分钟后变成 15 | 最小间隔限制生效 | 正常行为，系统会自动调整并提示 |
| 远端文件不存在 | 先拉取但远端尚无快照 | 先执行一次推送 |
| Gist 一直 401/403 | 使用了 Fine-grained Token | 改用 classic PAT 并勾选 `gist` scope |
| GitHub 仓库 Fine-grained Token 明明建了还是 401 | 忘记在 `Repository permissions` 里点击 `Add permissions`，或没把 `Metadata` / `Contents` 真正加进去 | 重新编辑 Token，添加 `Metadata: Read-only` 和 `Contents: Read and write` |
| 401 / 403（其他情况） | Token 无效或权限不足 | 重新生成 Token 并确认读写权限 |
| 拉取时报 `Can't modify workspace folder` | Edge 的工作区目录不允许扩展修改 | 插件已自动跳过非标准根节点，仅同步书签栏/其他书签/移动设备 |
| 误点了清空本地书签 | — | 设置页点击 `恢复最近清空的书签`，或导入清空时自动下载的备份 JSON |
| 冲突频繁 | 多设备并发改动 | 开启变更自动推送缩短窗口，或采用“先拉取再修改，改完立即推送” |
| 卸载扩展后重装，配置不见了 | 扩展使用 `chrome.storage.local` 保存配置 | 卸载通常会清空该存储，重装前请先导出配置备份 |

## 安全建议

1. 使用私有仓库 / 私有 Gist
2. Token 仅授予必要权限（仓库模式只给目标仓库的 Contents 读写；Gist 模式只勾 `gist`）
3. 不在公开场景泄露 Token；配置导出文件含 Token，同样注意保管
4. 定期轮换 Token
5. 强制覆盖、清空书签前先做 JSON 备份

### 0.2.0（2026-07-27）

- 架构重构：拆分为 `core / providers / background / ui` 纯 ESM 模块化结构，行为与存储格式完全兼容旧版，旧配置无缝迁移

## 快速回顾

1. 安装扩展并进入设置页填写平台配置（最快路径：GitHub Gist，仅需一个 classic PAT）
2. 保存设置并测试连接
3. 回到弹窗执行首次推送或拉取，确定“以哪一边为准”
4. 按需开启“书签变更后自动推送”与“定时自动推送”
5. 留意工具栏徽章：橙/红色 `!` 表示自动推送被跳过或失败，打开弹窗处理即可
